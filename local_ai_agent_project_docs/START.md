# PROJECT_GUIDE.md

## Общая идея

Создаём локального персонального ИИ-агента для Windows. По возможности
вся языковая обработка выполняется на компьютере пользователя с помощью
локальной модели, без платного облачного ИИ API.

Интернет всё равно понадобится для поиска информации и открытия сайтов.
«Локальный ИИ» не означает, что веб-сайты доступны без интернета.

## Планируемая архитектура

1.  Интерфейс: сначала простой текстовый интерфейс.
2.  Языковая модель: Ollama с локальной моделью.
3.  Оркестрация: Python-программа получает запрос, передаёт его модели,
    проверяет выбранное действие и вызывает соответствующий инструмент.
4.  Инструменты: сначала безопасное открытие заранее разрешённых URL;
    затем Playwright для взаимодействия с браузером.
5.  Голос: позже добавить локальное распознавание речи и локальный
    синтез речи.
6.  Удалённый интерфейс: позже телефон сможет отправлять команды
    компьютеру через защищённое соединение.

## Предварительно выбранные компоненты

### Ollama

Запуск локальной языковой модели и предоставление локального интерфейса
для обращений из Python.

Официальная загрузка: https://ollama.com/download/windows

### Qwen2.5 7B

Начальная модель-кандидат: `qwen2.5:7b`

Команда пробного запуска: `ollama run qwen2.5:7b`

Модель должна быть проверена на реальном компьютере. Если скорость,
качество или использование памяти окажутся неудовлетворительными, нужно
подобрать альтернативу.

### Python

Основной язык для реализации логики агента. Пользователь предпочитает
получать готовый код с комментариями и ясными инструкциями.

### Playwright

Планируемый инструмент для автоматизации браузера. Его будем подключать
только после проверки локальной модели и создания базовой
Python-программы.

## Принципы проектирования

-   Сначала реализовывать одну функцию и проверять её, затем расширять
    проект.
-   Не добавлять сразу много зависимостей и моделей.
-   По возможности избегать платных API и подписок.
-   Не считать локальную модель безошибочной: её выводы нужно проверять.
-   Не позволять модели произвольно выполнять любой сгенерированный код.
-   Разделять интерпретацию запроса и выполнение действия: модель
    предлагает действие, Python проверяет его и исполняет только
    разрешённые операции.
-   Перед удалением, отправкой сообщений, покупками, публикациями и
    другими потенциально опасными действиями требовать явного
    подтверждения.
-   Не хранить пароли, токены и другие секреты в открытом виде в коде
    или документации.
-   Не открывать агенту удалённый доступ из интернета без отдельного
    проектирования безопасности.

## Безопасность управления компьютером

На первых этапах агент должен иметь минимальные полномочия. Начать с
открытия разрешённых сайтов, а не с произвольного управления файлами и
командами PowerShell.

В дальнейшем: - использовать список разрешённых инструментов и
аргументов; - проверять URL и пути к файлам; - не выполнять команды
оболочки, которые модель сгенерировала сама, без проверки; - просить
подтверждение перед необратимыми действиями; - журналировать выполненные
действия без записи секретных данных.

## Ограничения и ожидания

-   Скорость зависит от модели, квантования, размера контекста и
    распределения нагрузки между GPU и CPU.
-   Даже если модель бесплатна и локальна, качество рассуждений может
    уступать более крупным облачным моделям.
-   Автоматизация сайтов иногда ломается из-за изменений интерфейса и
    авторизации.
-   Голосовые функции потребуют отдельных компонентов и проверки
    поддержки русского языка.
-   Телефонный доступ --- будущий этап; компьютер должен быть включён, а
    соединение должно быть защищено.

## Предпочтения пользователя по работе над проектом

-   Давать инструкции для PowerShell, а не CMD, если команды отличаются.
-   Пользователь новичок; объяснять действия последовательно.
-   Предоставлять полный готовый код, а не только фрагменты.
-   Добавлять комментарии к важным переменным, функциям и блокам логики.
-   Объяснять, в какой файл и куда вставлять код.
-   После каждого важного этапа просить запустить проверку и прислать
    результат.
-   Не предполагать, что команда выполнена успешно, пока пользователь
    это не подтвердил.
